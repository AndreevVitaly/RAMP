# Пробный запуск RAMP

Проект содержит Django API в `backend/` и статическую сборку Vite в `frontend/dist/`. Команды `runserver` и `npm run dev` предназначены только для локальной разработки. На хосте нужен сервер WSGI для `config.wsgi:application` и веб-сервер, который раздаёт сборку Vite, Django static и media.

## Перед публикацией

1. Создать PostgreSQL и отдельного пользователя БД. Для существующих локальных клиентов и проектов запланировать перенос данных: миграции создают пустую схему и не копируют записи из SQLite.
2. Установить зависимости из `backend/requirements.txt`, затем выполнить `python manage.py migrate`.
3. Создать `backend/.env` на сервере (не добавлять в Git). Обязательные значения: `DJANGO_DEBUG=false`, случайный `DJANGO_SECRET_KEY` длиной от 50 символов, `DJANGO_ALLOWED_HOSTS` с публичным доменом, `POSTGRES_*`. `USE_SQLITE` должен быть выключен. Установить `DJANGO_CSRF_TRUSTED_ORIGINS` для дополнительных HTTPS-доменов при необходимости.
4. Настроить HTTPS. Если TLS завершается на доверенном reverse proxy, включить `DJANGO_TRUST_PROXY_HTTPS=true` и передавать `X-Forwarded-Proto` только от этого proxy. По умолчанию Django перенаправляет HTTP на HTTPS, включает secure cookie и HSTS на один час в production. Увеличивать HSTS после проверки TLS.
5. Выполнить `python manage.py collectstatic --noinput`; раздавать `backend/staticfiles/` по `/static/` и `backend/media/` по `/media/`. Файлы media считать недоверенными, не исполнять их на веб-сервере. Сохранять media и БД при обновлении приложения и делать резервные копии.
6. Выполнить `npm ci` и `npm run build` в `frontend/`. Настроить один публичный origin: `/api/` и `/admin/` отправлять в Django, `/static/` и `/media/` раздавать из соответствующих каталогов, остальные пути — из `frontend/dist/`. Vite proxy работает только в режиме разработки.
7. Запустить `python manage.py check --deploy` с production-настройками. Создать Django superuser командой `python manage.py createsuperuser` или перенести существующую учётную запись. Сменить ранее использовавшийся пароль администратора.

## Почта и пробный доступ

До настройки SMTP гости могут открыть конструктор, но подтверждение email, личные кабинеты новых клиентов и отправка PDF по почте недоступны. В production консольный почтовый backend не выдаёт код регистрации. Для полноценного теста с близкими настроить `EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend`, `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `EMAIL_USE_TLS`, `DEFAULT_FROM_EMAIL`. Пароль приложения хранить только в переменных сервера. Затем указать адрес администратора в кабинете.

Запрос кода ограничен: один раз в минуту на email, пять раз в час на email и двадцать раз в час с одного IP. Если reverse proxy скрывает адреса посетителей, все запросы могут получить общий IP-лимит; настройте передачу реального IP через доверенную конфигурацию веб-сервера, не доверяя произвольному `X-Forwarded-For` от клиента.

После публикации проверить с телефона и ноутбука: открытие сайта по HTTPS, гостевой просмотр, загрузку фото администратором, запрет загрузки гостю, доставку кода, сохранение и открытие проекта, просмотр проекта администратором, отправку и скачивание PDF.
